# Pragmatic technical writing

Keep domain vocabulary and complete grammar. Use one term consistently for each concept. Separate instructions from explanations; put a condition before the action it controls. Use active voice and concrete verbs.

For instructions, use imperative sentences and aim for at most 20 words; for explanations, aim for at most 25 words and one topic per paragraph. Do not shorten by dropping articles or distorting the technical meaning. Split sentences when necessary; keep paragraphs and Markdown list items on one physical line.

Remove filler, vague claims, synonym rotation, and redundant qualifiers. Preserve meaningful uncertainty instead of turning a possibility into a certainty. State measured quantities with units and retain the original scope of each claim.

Check the longest sentences, repeated concepts, and conditional instructions once before delivering. Code, identifiers, CLI syntax, quoted errors, product names, and numerical facts remain exact. Use the strict catalog only if the user requests STE rule compliance or rule-numbered auditing.
